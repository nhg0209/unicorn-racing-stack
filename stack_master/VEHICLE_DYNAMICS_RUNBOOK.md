# 차량 동역학 측정 런북

`ggv.csv` / `ax_max_machines.csv` / `b_ax_max_machines.csv` 를 **추측이 아니라 실측**으로 쓰기
위한 절차. 그리고 **노면이 바뀌는 대회장에서 2분 안에 다시 맞추기** 위한 절차.

---

## 0. 왜 이걸 재는가

스택의 모든 가속 판단이 `ggv.csv` 의 `ay_max` 를 나눗셈 기준으로 쓴다 — 레이스라인 최적화,
반응형 플래너의 곡률 상한, 컨트롤러의 조향 클램프. 그 값이 틀리면 전부 같이 틀린다.

2026-08-12 실차 측정에서 드러난 것:

| | 설정값 | 실측 |
|---|---|---|
| `ay_max` (순수 횡) | 5.70 | **9.95** (원주행 좌 10.5 / 우 7.4) |
| g-g 포락선 모양 | 대칭 타원 (`dyn_model_exp` 2.0) | **비대칭** — 가속측만 무너짐 |

가속측 실측: `a_lat` p95 가 `a_x` +0.5 에서 7.60, +6.5 에서 **4.62**.
제동측은 8.5~9.95 로 거의 안 떨어진다. 대칭 타원은 이걸 표현하지 못한다.

**노면이 바뀌면 포락선의 크기만 바뀌고 모양은 유지된다.** 그래서 대회장에서는 스칼라 하나만
다시 재면 된다 (§4).

---

## 1. 사전 준비

```bash
source /opt/ros/jazzy/setup.bash && source ~/unicorn_ws/install/setup.bash
```

소싱을 빠뜨리면 `vesc_msgs` 를 못 찾아 `/vesc/sensors/core` 가 **조용히 빠진다**
(경고만 뜨고 녹화는 계속된다).

joy 한계를 올린다. `simple_mux` 는 파라미터 콜백이 없어 `ros2 param set` 이 안 먹는다:

```bash
ros2 launch stack_master race.launch.xml map:=<map> joy_max_speed:=8.0
```

안 올리면 T1·T2 가 4.0 m/s 에서 잘린다 (기본 `joy_max_speed: 4.0`,
`joy_max_steer: 0.4` — 2026-08-12 원주행 bag 이 정확히 이 두 값에서 멈춰 있다).

```bash
ros2 bag record -o ~/vehdyn_$(date +%m%d_%H%M) --topics /rosout /tf_static \
  /vesc/sensors/imu/raw /vesc/sensors/core /vesc/odom /vesc/ackermann_cmd \
  /vesc/high_level/ackermann_cmd /vesc/commands/servo/position \
  /vesc/commands/motor/speed /car_state/odom /car_state/odom_frenet
```

**전 항목을 한 번의 녹화에 담는다.** 항목 사이는 정지로 구분한다.

## 2. 시험 항목

### T0 · 정지 5초 — 시작할 때, 그리고 **매 항목 사이마다**

자이로·가속도계 바이어스를 여기서 뽑고, 구간 분할도 이걸로 한다. **빠뜨리면 분석이 어려워진다.**

### T1 · 직선 전가속 ×3
정지 → 스틱 끝까지 → 최고속. → **`ax_max_machines.csv`** (속도별 구동 한계).
저속은 트랙션 한계, 고속은 모터 출력 한계라 곡선이 된다.

### T2 · 직선 전제동 ×3
최고속 → 스틱 뒤로 끝까지 → 정지. → **`b_ax_max_machines.csv`**.

### T3 · 워시아웃, **느린 램프** — 좌/우 각 2~3바퀴  ← **대회장 표준 시험**
작은 원, 조향을 한 값에 고정, **아주 천천히** 가속. 원 밖으로 밀려나기 시작하는 지점이 한계.

→ **`ay_max` 순수 횡** (`a_x ≈ 0`).

> 천천히가 핵심이다. 빨리 가속하면 종가속이 섞여 T4 가 된다.

### T4 · 워시아웃, **빠른 램프** — 좌/우 각  ← **이번 시험의 핵심**
T3 과 **같은 조향값**으로, 저속에서 공격적으로 가속해 밀려날 때까지.

→ **가속측 g-g 포락선.** 실측이 가장 많이 무너지는 구간이고, ifac_0807 슬라럼(s 4.3~5.8)에서
정점 통과 중 가속해 `|d|` 가 +0.04 → +0.43 으로 벌어지는 현상의 정체다.

### T5 · 원 안에서 제동
원에 속도를 싣고 들어가 **조향을 유지한 채** 제동. → **제동측 포락선.**
레이싱 데이터에서 제동측이 거의 안 무너지는 것이 의외라 확인이 필요하다.

### T6 (여유 있으면) · 조향값을 바꿔 T3~T5 반복
더 큰 원(조향 절반)으로. 포락선이 속도에 따라 변하는지 본다.

## 3. 실행 시 지킬 것

- **T3·T4·T5 는 같은 조향값.** 그래야 같은 포락선 위의 점이 된다
- 조향은 손으로 고정 — 미세한 흔들림은 괜찮고, 크게 바꾸지 않는다
- **좌우를 반드시 쌍으로.** 2026-08-12 측정에서 우측이 좌측보다 30% 약했다
  (풀락 4 m/s: 좌 `a_lat` 10.5 / 우 7.4). 대칭으로 가정하면 우코너에서 과대평가한다
- **같은 노면·같은 타이어·한 세션.** 다른 세션 데이터를 같은 포락선에 올리지 않는다
- 밀려나가는 것이 **눈에 보일 때까지.** 애매하면 데이터에서도 애매하다

### 필요 공간

**4 × 4 m 면 된다.** 2026-08-12 원주행의 실제 반경은 **0.62 ~ 1.42 m** 였다
(지름 1.2~2.8 m). `a_lat = v²/R` 이므로 반경이 작을수록 낮은 속도에서 한계에 닿는다 —
R=1 m 면 3.2 m/s 에서 10 m/s² 다. T1·T2 는 직선 15~20 m 가 필요하다.

## 4. 대회장 절차 — 노면이 다를 때

**옮겨가는 것과 안 옮겨가는 것이 다르다.**

| 옮겨감 (노면 무관) | 안 옮겨감 (노면별) |
|---|---|
| 포락선의 **모양** — 가속/제동 비대칭, 지수 | **크기** — `ay_max`, `ax_max` |
| 조향 게인·오프셋, 좌우 비대칭 (기계 기하) | |
| 컨트롤러 구조, IMU 배선 | |

그래서 대회장에서는 **스칼라 하나**만 다시 재면 된다.

### 표준 경로 (공간이 있을 때)

| | 시간 |
|---|---|
| **T3 워시아웃 좌·우** | **2분** |
| `ggv.csv` 의 `ay_max`, `ax_max` 에 `k` 곱하기 | 1분 |
| 레이스라인 재생성 | 몇 초 |
| 클린 랩으로 `\|d\|` · 랩타임 확인 | 3분 |

```
k = ay_max(대회장) / ay_max(연습장)
```

**연습장 T3 값을 반드시 기록해 둘 것.** 기준이 없으면 비율을 못 낸다.

### 공간이 없을 때 — 대체 측정

우선순위 순으로, 전부 별도 공간이 필요 없다.

1. **워밍업 랩의 언더스티어 무릎** ← 가장 좋다
   기구학 요구(`v·tan δ/L`)와 실측 요레이트(IMU gz)의 비를 요구 크기별로 본다.
   비가 1.00 을 유지하다 무너지기 시작하는 지점이 그 노면의 결합 한계다.
   **트랙 기하와 무관하고 별도 공간이 필요 없다.** 차가 가끔이라도 한계에 닿는 랩이면 된다.
   2026-08-12 연습장 기준값: 비 1.00 이 요구 6 까지 유지, 그 위에서 0.53 으로 붕괴.

2. **워밍업 랩의 달성 `a_lat` 상단**
   IMU 에서 `|v·gz|` 의 p95/p99. 연습장 기준값 p95 8.55 / p99 10.06.
   **하한만 준다** — 차가 보수적으로 달리면 한계에 안 닿아 과소평가한다.
   대회장 값이 연습장보다 낮게 나와도 "그립이 낮다"고 단정하지 말 것.

3. **메인 직선에서 전제동 1회**
   종방향 한계를 주고, 포락선 모양이 유지된다는 가정 아래 나머지를 스케일한다.
   직선은 어느 트랙에나 있다.

4. **피트/패독의 좁은 회차**
   2~3 m 지름 원이면 걷는 속도~조깅 속도로 횡 한계에 닿는다. §3 참조.

### 재생성할 시간도 없을 때

`speed_scaling.yaml` 의 `global_limit` 은 **[0,1] 클램프**다 — 내리는 것만 된다
(1.0 초과는 `sector_tuner` 를 죽인다). 속도를 `k_v` 배 하면 횡가속은 `k_v²` 배다.

| `global_limit` | 감당 가능한 그립 감소 |
|---|---|
| 0.95 | 10 % |
| 0.90 | 19 % |
| 0.85 | 28 % |

**그래서 레이스라인은 낙관적으로 생성하고 미끄러우면 내린다.** 반대로 하면 되돌릴 방법이 없다.
다만 속도만 내려가고 **라인 기하는 높은 그립 기준 그대로**(에이펙스가 타이트)라, 급할 때의
안전판이지 정답은 아니다.

## 5. 단일 변경점 조건

`k` 를 곱하는 곳이 `ggv.csv` 하나이려면 **모든 소비자가 그 파일을 읽어야** 한다.

| 소비자 | 상태 |
|---|---|
| 레이스라인 최적화 | ggv 읽음 |
| 반응형 플래너 곡률 상한 | ggv 읽음 |
| 컨트롤러 조향 클램프 | ggv 읽음 |
| 마찰원 가속 제한 | 예정 |
| `static_avoidance_node:201-203` | **하드코딩** (`a_lat_max 6.0`, `a_long_max 4.0`, `a_long_accel 3.0`) |

**마지막 줄이 남아 있으면 대회장에서 손으로 찾아 고쳐야 한다.**

## 6. 산출물

이 bag 하나로 다음이 나온다.

1. `ay_max` 실측 (좌/우, 순수 횡) — `ggv.csv` 에 들어갈 값
2. `ax_max_machines` / `b_ax_max_machines` 곡선
3. 비대칭 g-g 포락선 — 가속측/제동측 따로, 대칭 타원으로 표현 가능한지 판정
4. 현재 설정(5.7 / 7.0 / exp 2.0)과의 차이, 재생성 시 예상 랩타임
5. **대회장 재현용 T3 기준값**

> `ggv.csv` 를 바꾸면 **반드시 레이스라인을 재생성해야 한다.** 차가 따르는 속도는
> `global_waypoints.json` 의 `vx_mps` 이고 그건 오프라인 산출물이다. 온라인 경로는 그 값을
> 낮출 수만 있고 올릴 수 없다 — 스택 재시작으로는 아무 일도 일어나지 않는다.
