# UNICORN Stack — Working Rules (read first)

## Process
- NEVER run `colcon build` or any build command. The user builds manually. After edits, state which packages need rebuilding.
- NEVER push to `origin` (HMCL-UNIST official). Push only to `personal` remote, and only when asked.
- Commit messages in English, scoped like existing history (`fix(static-avoidance): ...`). User-facing explanations in Korean.
- Do not modify mapping-related code (cartographer configs, mapping_2d.lua, finish_map.py). localization_2d.lua num_subdivisions_per_laser_scan stays 10.
- Plan-first: before editing, list files you will touch and why; keep diffs minimal. Line numbers given in prompts are evidence pointers — re-verify against the actual code before editing.

  - static_obstacle_layer — no yaml and no launch params at all; every value is the declare_parameter default in the node.
  - multi_tracking — opponent_tracker_params.yaml + save_yaml (rqt save button). ## Static re-optimization: one solver
- `closed_reopt.py` — pick a side per box -> turn each keep-out into corridor bounds analytically -> multiply the corridor by a hard envelope (locality x remaining curvature budget) -> solve `min ||D2 d||^2 + w||d||^2 s.t. lo <= d <= hi` ONCE with quadprog, no iteration, at every published station -> anything it cannot clear by obs_margin + w_veh/2 is dropped and NAMED on /static_reopt/coverage for the reactive layer. `closed_reopt_bridge.py` shapes the result into what the node's vetoes read.
- The C2-quintic-hump pipeline (`reoptimize_local_window`, the apex/knot machinery, the reach search, the relax ladder) and the whole-track `reoptimize_with_obstacles` are DELETED — `git log -- planner/gb_optimizer/gb_optimizer/static_reopt_core.py` has them. There is no `reopt_method`: with a fallthrough branch, any typo in it selected a solver that takes minutes per solve.
- `static_reopt_core.py` is now only what the bridge and the node still need: the publishing tail (uniform resample, curvature republish, velocity/accel), `_wrap_normals`, `build_wpnts`, `load_reftrack`.

## Coupled invariants
- **Changing `veh_dyn_info/ggv.csv` (ay_max / ax_max) REQUIRES regenerating the raceline.** The speed the car follows is `vx_mps` in `stack_master/maps/<map>/global_waypoints.json`, an OFFLINE product of the global optimizer. `closed_reopt_bridge` republishes those values unchanged (`:126` seeds vx from clean_vx, `:159` restores it where the geometry rejoins the raceline) and consults ggv only to cap them FURTHER (`_cap_speed_to_published_curvature`). The online path can lower vx and can never raise it, so a bigger ggv number buys nothing until the raceline is rebuilt from it — restarting the stack does not do it. ifac_0807 WAS rebuilt from the 2026-08-11 ggv (est_lap_time 13.896 -> 12.229 s, iqp vx max 6.814 -> 7.848), so that map is consistent; any OTHER map still carries a raceline optimized against the old envelope. ggv's ay_max is also the lateral budget the reactive planner's curvature cap divides by, so it moves avoidance speeds too, not just raceline speeds. **CAR and SIM carried different ay_max on purpose** (4.5 vs 8.0) so that sim tuning of anything dividing by ay_max did not transfer to the car; since 2026-08-11 both are **5.7** (ax_max 7.0), i.e. that divergence was collapsed and sim IS now meant to predict the car. Treat the equality as load-bearing rather than incidental, and re-check it before quoting either file. For the same reason no offline GATE may be expressed in a unit that contains ay_max: `sweep_static_feasibility` gates the geometric `mean sqrt(1/|kappa|)` and only REPORTS the speed, labelled with the a_lat_max it used.
- Margin chain (line-center → obstacle-EDGE everywhere): SM static GB requirement (gb_ego_width_m/2 + lateral_width_static_gb_m) ≤ planner clear-gate stay (width_car/2 + clear_margin_m) ≤ enforced reopt clearance floor − slack. After ANY margin change run python3 stack_master/scripts/check_avoidance_margins.py (exit 0).
- Curvature/lateral-accel judgments use real geometry (Menger), never the kappa_clean + d''-additive model (proven ~45% low on ifac).
- ifac's own raceline peaks at |kappa| 1.448 against a curvlim of 1.5 (96.5%). Two things are forbidden and one is not. FORBIDDEN: comparing your published curvature to ANOTHER solver's published curvature (the hump's uniform resample reads 1.4378 where the raceline it was built from measures 1.4478 — you would be measuring the resampler); and anchoring a gate to the CLEAN line's peak, which penalises a flatter raceline for being flatter (a candidate whose published worst was 1.246 failed a gate a shipped line passed at 1.451). FINE: checking that a line stays inside the budget its own formulation declared (closed_reopt's kappa_budget) — that anchor does not move when the raceline is regenerated. Report clean-line increments; never gate on them.
- hold_horizon_m (lane_change) > interest_horizon_m (SM); static planner lookahead ≥ global_tracking max_horizon.
- **The two avoidance planners may never both claim one obstacle.** static_avoidance treats a dynamic-flagged obstacle as STATIC below `static_near_zero_mps` (0.15) held `static_promote_sec`; lane_change may ENGAGE one at or above `engage_min_vs_mps` (0.35) held `engage_moving_s`. OVERLAP = a static keep-out one way and a lane change the other way on the same box, which is how run_0810_2102 put a 1.58 m step into the reference, saturated the steering for 16 cycles and hit the wall. check_avoidance_margins.py fails if `engage_min_vs_mps < static_near_zero_mps`. The GAP between them (0.15-0.35 m/s, sustained) is owned by neither, resolves to TRAILING, and is DELIBERATE — closing it re-admits the 0.20 m/s reading that engaged on a stationary box. `not o.is_static` alone is not a moving test: staticFlag is None until min_nb_meas, so every fresh track publishes is_static=False. See planner/lane_change_planner/ENGAGE_GATE_NOTE.md.
- A "SWAPPED d_left/d_right" warning from static_avoidance_node or change_avoidance_node is NOT evidence to regenerate a map. Both compare a grid corridor measured through `self.converter` (built from **/global_waypoints**, which static_reopt swaps instantly) against d_left/d_right read from **/global_waypoints_scaled** (sector_tuner's 0.5 s timer) — two different lines for up to that long, which `_anchor_car_idx`'s own docstring already documents. On ifac_0807 the static one fired 0.132 s after a swap (391.838 -> 391.970) and change_avoidance's `dis` is a MAX over the whole ~22 m solve span against a per-station 0.5 m threshold, so one station arms it. Neither message ever TESTS the near-mirroring it then asserts (observed wpnt [-1.21,+0.69] vs grid [-2.05,+0.75] is not a mirror). Confirm with check_track_bounds.py before touching a map.
